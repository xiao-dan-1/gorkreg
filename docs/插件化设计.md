# 插件化设计（v0.1.0-baseline 之后）

> 基线：`git tag v0.1.0-baseline`（`afe6de2`）  
> 状态：**P0 已实施**（mail/captcha 工厂）；**P1 已实施**（`pipeline/register.py`）；**P2 已实施**（`backends/export`：cpa 落盘 + pool；upload 仍 `--cpa-upload`）  
> 原则：横切可插拔 · 协议核心少动 · 单平台克制 · 行为先不变

---

## 1. 目标与非目标

### 目标

1. **mail / captcha / export** 三条横切能力可替换（统一接口 + 名字选择）。
2. **注册流水线**从 `cli.py` 抽出，CLI 只解析参数与调度。
3. **结果契约稳定**，下游池 / 上传 / 重试不绑具体后端。
4. 重构分阶段，**每阶段行为与 baseline 一致**（可 diff 命令输出）。

### 非目标（明确不做）

| 不做 | 原因 |
|------|------|
| 多平台 `BasePlatform` + 全量 registry | 当前只有 Grok |
| Electron / Web UI / provider catalog DB | 过重 |
| 浏览器兜底回主链 | 已定纯协议 |
| 借重构大改 `client.py` 协议细节 | 证据不足不大改 |
| AAR 级生命周期产品台 | 现有 CLI ops 够用 |

## 4. 接口契约（最小）

### 4.1 Mail

```python
class MailBackend(Protocol):
    def wait_for_xai_code(
        self,
        after_ts: float = 0,
        timeout: int = 120,
        interval: int = 3,
    ) -> str: ...
```

| name | 实现 | 备注 |
|------|------|------|
| `graph` | `MSMailClient` | 默认 |
| `imap` | `OutlookIMAPClient` | `--mail-backend imap` |

工厂：`get_mail_backend(name, account, *, proxy, api_url, cfg) -> MailBackend`

### 4.2 Captcha

```python
class CaptchaBackend(Protocol):
    def solve_turnstile(self, website_url: str, website_key: str) -> str: ...
```

| name | 实现 |
|------|------|
| `twocaptcha` | 现有 `TwoCaptchaSolver` |
| `yescaptcha` | 现有 `YesCaptchaSolver` |
| `auto` | 现有 `solve_turnstile_auto` 策略（默认） |

工厂：`get_captcha_backend(name, cfg) -> CaptchaBackend`  
**不**在接口层塞 Castle / 指纹；协议细节留在 `client` / solver 内部。

### 4.3 Export

```python
class ExportBackend(Protocol):
    def save_cpa(self, email: str, payload: dict) -> Path: ...
    # 可选能力，无则 NoOp 或独立 ops 命令
    def upload(self, paths: list[Path] | None = None) -> dict: ...
```

| name | 行为 |
|------|------|
| `cpa_files` | 写 `cpa_export/xai-{email}.json`（必须路径） |
| `auth_pool` | 更新 `auth.json` 账本 |
| `cpa_api` | `POST {base}/v0/management/auth-files` |

策略组合（配置，非类爆炸）：

```yaml
# 概念；实施时再落 config，默认保持现状
export:
  local: cpa_files          # 必须
  pool: auth_pool           # 现有 import/同步逻辑
  remote: null              # 或 cpa_api；默认不自动推，用 --cpa-upload
```

与 share 一致：**本地归档必须，远程/热加载可选**。

### 4.4 注册结果契约

无论后端如何换，`register_one` / batch 单条结果至少含：

```text
email, password, sso, code,
cpa_path | None,
error, error_code, retryable,
proxy_sid, proxy_region,
timings_sec, elapsed_sec, created_at
```

与现有 `errors.annotate` / `--retry-failed` 对齐，**字段只增不改名**。

## 5. 流水线边界

```text
[proxy resolve] → load_signup → create_code
    → mail.wait_for_xai_code
    → verify_code → captcha.solve_turnstile
    → create_account → SSO
    → (可选) mint CPA → export.save_cpa
    → 统一 result dict
```

| 层 | 职责 | 禁止 |
|----|------|------|
| `pipeline/register.py` | 步骤顺序、超时、结果字典 | 具体 HTTP / 打码协议细节 |
| `protocol/*`（client…） | gRPC-web / Server Action / SSO / device-code | 选 graph 还是 imap |
| `backends/*` | 可替换 I/O | 改注册步骤顺序 |
| `cli.py` | 参数、并发、日志、调 pipeline/ops | 复制粘贴业务步骤 |
| `ops` | env-check / mint / refresh / upload / pool | 塞进 register 成功路径强制执行远程上传 |

**代理：** 保持「注册链 7890+辣椒 / mint·外网 10808」分场景；工厂入参带 `proxy`，不在 backend 内写死端口。

## 6. 工厂机制（选轻不选重）

实现数量 2–4 → **dict 工厂**，不用装饰器 registry：

```python
MAIL_BACKENDS = {
    "graph": GraphMailBackend,
    "imap": ImapMailBackend,
}

def get_mail_backend(name: str, ...) -> MailBackend:
    key = (name or "graph").lower()
    cls = MAIL_BACKENDS.get(key)
    if not cls:
        raise ConfigError(f"unknown mail backend: {name}", code="mail_backend")
    return cls(...)
```

新增后端：加一个模块 + 工厂一行。等真有 5+ 且需动态发现时再考虑 `@register`。

## 7. 分阶段实施

| 阶段 | 内容 | 验收 | 风险 |
|------|------|------|------|
| **P0** | `backends/mail` + `backends/captcha`：Protocol + 适配旧类 + 工厂；CLI 注册路径改走工厂 | 同账号 dry 路径与 baseline 行为一致；`--mail-backend graph|imap` 仍可用 | 低 |
| **P1** ✅ | `pipeline/register.py` 抽出；`cli.py` 变薄（`--register` / `--batch` 调 `register_one`） | import/help/env-check/auth-status；batch 结构与 retry-failed 仍在 cli | 中 |
| **P2** ✅ | `backends/export` 收拢 cpa 落盘 + pool；upload 仍以 `--cpa-upload` 为主 | mint 落盘路径不变；export 工厂 ad-hoc；upload 本机 list | 中 |
| **P3** | 可选 `protocol/` 目录归拢；**不**上多平台 | import 兼容 | 低收益 |

每阶段：

1. 从 `v0.1.0-baseline` 或当前 main 开分支（如 `feat/backends-p0`）。
2. ad-hoc `hermes-verify-*`：工厂解析、旧命令 help、dry-run / env-check。
3. **不**顺手改 Turnstile / 指纹 / 建号字段。

## 8. 配置约定

- 密钥继续 **只进 `.env`**（`CPA_SECRET_KEY`、打码 key 等）。
- 项目 `config.yaml` 的 `cpa:` 保持 KISS：`base_url` + `secret_key` + `auth_dir`。
- 后端选择优先 **CLI 已有参数**（`--mail-backend`），其次 config 可选默认值；避免一次加十几个 yaml 键。
