# Grok 纯协议注册 · 流程运维手册

> 面向日常使用的短手册见仓库根目录 [README.md](../README.md)（用户手册）。本文为开发/运维详版。


按**注册流水线**写：每一步 = 目标 + 操作命令。  
密钥只放本地 `.env` / `config.yaml`，**勿提交、勿贴聊天**。

项目根执行（Windows cmd 也可复制）。`scripts/*.py` 已自举路径，**无需** `PYTHONPATH=.`。

---

## 总流程（先看这一张）

```text
步骤1  环境就绪          --env-check / 配 .env（打码：Cap 或 Yes）
  ↓
步骤2  代理可用          --check-chain（注册链 7890；拒跑勿盲 skip）
  ↓
步骤3  产号拿 SSO        3A CloudMail 或 3B Outlook（同级）
  │                      打码：auto|yescaptcha|capsolver|twocaptcha
  │                      产线 j 见「3A·并发与效率」；KPI=ok%+成功号 p50
  │                      失败 → 「3·失败后重试」
  │                        · 3A: probe_sso_failed / proxy-retries（wire·TLS）
  │                        · 3B: --retry-failed N（批末 retryable）
  ↓
步骤4  确认库存          sso_roster / --summary（有 SSO 才算过）
  ↓
步骤5  取证入账 + 出包   mint → auth.json；按需 --export cpa|sub2api
  ↓
步骤6  保活 token        --refresh --needs-refresh-only --remint-on-revoke
  ↓
步骤7  探活 / 查额度     --probe-quota models | billing | chat | quota
  ↓
步骤8  上传远端（可选）  --cpa-upload --cpa-missing（要先有 cpa_export）
```

| 角色 | 端口 / 文件 | 用途 |
|------|-------------|------|
| 注册链 hop1 | **7890** | 动态 IP；**禁止用 10808 顶注册** |
| 注册 / mint / probe 本地口 | **LOCAL_PROXY**（默认 **7890**） | 同一 Clash hop；勿再配 MINT_PROXY |
| 打码 API | 直连或本机代理 | Yes / CapSolver / 2C（密钥 `.env`） |
| 通过号 | `sso_roster.txt` + `output/accounts/account_*.json` | **有 SSO 且无 error**（单号/batch 成功都会 append cli） |
| 凭证账本 | `auth.json` | mint 默认只入账；export / list 的真源 |
| 本地 xAI pack | `cpa_export/xai-*.json` | **按需** `--export cpa`（≡ cpa_files）或 `--mint-write-cpa` |
| sub2api pack | `sub2api_export/grok-*.json` | **按需** `--export sub2api`（UI 数据导入外壳） |

架构一句话：

```text
SSO ──mint──► RT/AT ──auth.json──► --export cpa | sub2api
```

日常维护若**已有号池**，可从步骤 5 或 6 起跳，不必每次产号。

## 步骤 3 · 产号拿 SSO

**目标**：拿到 `邮箱----密码----SSO`，写入 `sso_roster.txt`（`email----password----sso`，密码只在 output 证据）。  
下面 **3A / 3B 同级**，按邮箱来源二选一（或混用）。

### 3A · CloudMail（推荐，自建 catch-all）

```bash
# 单号（成功会写 output/accounts + sso_roster）
python main.py --register-cloudmail -v
# 点名打码：--captcha-backend capsolver|yescaptcha|auto

# 稳产（推荐 j=2～4）
python scripts/prod_cloudmail_batch.py -n 20 -j 2 --ascii-log
python scripts/prod_cloudmail_batch.py -n 20 -j 4 --ascii-log

# 冲量（j=6～8；开跑前必 --check-chain）
python scripts/prod_cloudmail_batch.py -n 50 -j 6 --ascii-log
python scripts/prod_cloudmail_batch.py -n 50 -j 8 --ascii-log

# 压测窗口（j=10～12；代理健康时）
# python scripts/prod_cloudmail_batch.py -n 40 -j 12 --ascii-log

# 默认安静 + 完成行 # 进度；过程日志加 -v
python scripts/prod_cloudmail_batch.py -n 5 -j 2 --ascii-log -v

# 调试：关预热 / 关 scrape 缓存
python scripts/prod_cloudmail_batch.py -n 5 --no-scrape-prewarm
python scripts/prod_cloudmail_batch.py -n 5 --no-scrape-cache

# 网络类失败同邮再试次数（默认 1；含 curl28/35、wire-type parse）
# python scripts/prod_cloudmail_batch.py -n 20 -j 6 --proxy-retries 1
```

打码插件（单号 / batch / prod **同一工厂**）：

| 开关 / 配置 | 含义 |
|-------------|------|
| `--captcha-backend auto` | Yes → CapSolver → 2C → …（余额 preferred / soft-skip） |
| `--captcha-backend capsolver` | 只打 Cap（推荐有 key 时点名） |
| `--captcha-backend yescaptcha` | 只打 Yes |
| `--captcha-backend twocaptcha` | 只打 2C |
| env `CAPTCHA_BACKEND` | 无 CLI 时覆盖 yaml（`auto` 是合法显式值） |
| `config captcha.backend` | 兜底默认 |

优先级：**CLI > CAPTCHA_BACKEND > config > auto**。  
余额预检：`getBalance` **进程内 TTL 缓存 + single-flight**（`e495d3e`）；j≥8 勿再每号齐射打爆 Cap。  
点名 `capsolver` 时报告行可见 `Yes=skip`（未探测，**不是**空钱包）。

| 产出 | 路径 |
|------|------|
| 账号 JSON | `output/accounts/account_*.json`（旧根目录可 `--migrate-account-evidence`） |
| 批摘要 | `output/prod_cloudmail/batch_*.{md,json}` |
| bench | `output/bench_runs.jsonl` · `bench_summary.md`（prod 结束自动写） |
| 效率台账 | `output/efficiency/` · 操作卡 `docs/efficiency-playbook.md` |
| 花名册 | 成功则追加 `sso_roster.txt`（`email----password----sso`） |

预热默认开：只 GET 注册页，**不烧号**。  
prod 默认 **`--proxy-retries 1`**：同邮箱网络/parse 类失败再跑 1 次（新 SID，不 realloc）。  
**没有** 3B 那种批末 `--retry-failed`；SSO 洞见下方「3·失败后重试」。

#### 3A · 并发与效率（2026-07 真机 · CapSolver）

| j | 角色 | 证据 / 备注 |
|---|------|-------------|
| 1～2 | 稳产 / 排障 | 最稳 |
| **4** | **吞吐甜点** | j4 多批全绿；日常优先 |
| **6～8** | **冲量** | j8n50 / j8n80 **100%**（修 getBalance 后） |
| 10～12 | 压测冲量 | j10n50 / j12n40 **100%**；先 check-chain |
| 成功号 p50 | **~8.0～8.8s** | stage：sso~3s > create/verify/wait~1.3～1.8s > **turnstile~0.9s** |

KPI：**ok% ≥ 75%** 与 **成功号 elapsed p50**；wall 会被 1～2 条 TLS/retry 长尾抬高，勿单独当吞吐。  
修前坑：j8 每号 `getBalance` 齐射 → Cap `ERROR_RATE_LIMIT` → 假 ok% 崩（已修）。  
仍可能偶发：`wire type` / curl(35) → 日志见 `parse_error → retry` / `proxy/network fail → retry once`（最终常 OK）。  
preflight **FAIL**：0 烧号退出；等 15～30s 再 `--check-chain`，**勿**立刻 `--skip-proxy-preflight`。

### 3B · Outlook 号池（旧路径）

```bash
# mails.txt 每行：email----password----client_id----refresh_token
python main.py --batch mails.txt --region US -v

# 并发 + 批末对 retryable 失败串行补跑 2 轮（默认已是 1 轮）
python main.py --batch mails.txt --region US -j 2 --retry-failed 2 -v

# 关掉批末自动重试
python main.py --batch mails.txt --region US --retry-failed 0 -v
```

收码 graph/IMAP 看配置；`mail_timeout` 不会第一次就 auto-dead。  
`--retry-failed N`：**仅 3B**；只补标记为 retryable 的失败（代理/邮件/打码抖动），不是所有 error。

**同根别名（扩容轴，上限未知）**：同一 Outlook **主号**下的**别名**也可当独立邮箱注册；码进主箱，仍用主号 RT 收码。  
**≠** CloudMail catch-all。每根号能挂多少个别名**未测死** → 台账 `docs/outlook-alias-register.md` + `output/outlook_alias_ledger.md`。  
单号 plus：`python main.py --register "root----pw----cid----rt" --signup-email "rootlocal+tag@outlook.com" -v`（`local+tag@`，码进主箱）。结果 `is_alias`/`mail_root`。上限未知→台账。

### 3 · 失败后重试（产号步骤专用）

先看失败分桶，再选命令。有 SSO 的成功号**不要**当失败重试。

| 现象 | 多半原因 | 重试命令 |
|------|----------|----------|
| `sso_failed`（body 常 ~56699） | create 短 body / SSO 抠不出 | **3A**：`probe_sso_failed`（下）或同邮箱串行再跑 |
| `mail_timeout` | 收码慢/邮件站 | 同邮箱再跑；3B 可吃 `--retry-failed` |
| `create_code` / curl 28 / **curl 35** | 代理/TLS 瞬时 | prod 默认 `--proxy-retries 1`；仍挂再单号 |
| **`parse_error` / `wire type`** | gRPC 脏包/截断 | 进程内 1 次重试 + prod proxy-retry（`1528e55`）；勿当协议坏 |
| **`captcha_balance` + RATE_LIMIT** | 旧：每号 getBalance 齐射 | 应已缓存；若再现查 `e495d3e` / 勿盲加 j |
| `Turnstile prefetch failed` + TASK_NOT_FOUND | Cap 任务过期 | **可恢复**：自动 sync 重打；偶发可忽略 |
| 代理 / captcha 抖动 | 瞬时 | 3B：`--retry-failed N`；3A：proxy-retries / 再跑 batch |
| `email_already_in_use` 等 | 服务端已有号 | **停**；有密码可继续 probe 抠 SSO，勿当「未注册」狂开新号 |
| preflight FAIL TLS | 住宅链窗口差 | **0 烧号**；等 + `--check-chain` 再跑 |

#### 3A 补 SSO（推荐指令）

```bash
# 指定邮箱（可多个；串行；复用 output 里旧 password）
python scripts/probe_sso_failed.py a@bj01.xdauv.xyz b@bj01.xdauv.xyz

# 自动扫 output/ 最新 account_*.json：无 sso 且 error 含 sso_failed
python scripts/probe_sso_failed.py --from-output

# 并发（默认 -j 1；补洞建议 ≤3，过高易再 sso_failed）
python scripts/probe_sso_failed.py --from-output -j 3
python scripts/probe_sso_failed.py a@dom b@dom c@dom -j 2

# 混用：手写 + 扫描
python scripts/probe_sso_failed.py known@dom --from-output
```

| 项 | 说明 |
|----|------|
| 输入 | CLI 邮箱 和/或 `--from-output`；都空则读脚本内 `TARGETS`（默认可空） |
| `-j N` / `--jobs N` | 并发 worker（**默认 1=串行**） |
| 成功 | 更新 `output/accounts/account_*.json`；`sso_roster` 缺行则追加（写盘加锁） |
| 摘要 | `output/sso_rescue/probe_*.md` + `.json`（含 `jobs=`） |
| 退出码 | 全部救回 0；有失败 1；无目标/preflight 拒 2 |

同邮箱「再产一轮」也行（CloudMail **无**批内 auto-retry，补洞请用串行）：

```bash
python scripts/prod_cloudmail_batch.py -n 1
```

#### 3B 批末自动重试

```bash
python main.py --batch mails.txt --region US -j 2 --retry-failed 2 -v
```

| 开关 | 含义 |
|------|------|
| `--retry-failed N` | 主批结束后，对 **retryable** 失败串行再跑 N 轮（默认 1） |
| `--retry-failed 0` | 关闭 |
| 非 retryable | 不进补跑（如部分永久 mail 死号） |

### 本步通过标准

- JSON 有 **sso** 且 **无 error**
- 已进 `sso_roster.txt`
- 无 SSO 的 JSON 可留作补救，**不算**正式库存；用「3·失败后重试」处理后再进步骤 4

## 步骤 4 · 确认库存

**目标**：看 **auth.json 凭证账本**（唯一库存源）：多少号、是否 fresh、谁要刷。

### 操作

```bash
python main.py --summary
python main.py --summary --summary-domain bj01.xdauv.xyz
python main.py --summary --summary-full --summary-limit 30
python main.py --summary --auth-file path/to/auth.json
```

`--summary` **只读 auth.json**：

| metric | 含义 |
|--------|------|
| **total** | 账本条目（按 email 去重） |
| fresh / needs_refresh / expired | AT 时钟态（skew 默认 5min） |
| with_rt / with_at | 有 refresh / access |

## SSO 三落点（台账约定）

注册成功后 SSO 可能出现在三处，**用途不同，不要混成一个文件**：

| 落点 | 文件/位置 | 角色 | 谁写 | 谁读 |
|------|-----------|------|------|------|
| **可 mint 台账（SSO 花名册）** | `sso_roster.txt`（`email----password----sso`） | 有 SSO 才能进步骤 5 | register 成功 / probe 补救 append | `--mint` / remint / pipeline publish |
| **审计证据** | `output/accounts/account_*.json` | 单号结果、失败 error、排错 | register / probe_sso_failed | `--summary`（evidence 层）、补救扫描 |
| **当次内存** | pipeline `register_rows["_sso"]` | 一条龙当次 publish，不落盘 token 打印 | `prod_pipeline` 注册成功行 | 同进程 `phase_publish` |

**优先级（对账时）**

1. 要 mint / remint → 以 **sso_roster 有该邮箱 SSO** 为准（缺则先补写，再 mint）。
2. 要查失败原因 → 看 **output/accounts/account_*.json** 的 error / 有无 sso 字段。
3. 一条龙当次跑 → 内存 SSO 优先于再读盘；进程结束即无。

**禁止**

- 用 `cpa_export` 当 SSO 源（那是 export pack）。
- 把 output JSON 当唯一台账却不写 sso_roster（mint-missing 会漏号）。
- 在日志/进度行打印完整 SSO / RT / AT。

**mail 实现位置**

- 规范实现：`grokreg/backends/mail/*`（graph / imap / cloudmail）。
- 根目录 `mail.py` / `mail_cloudmail.py` / `mail_imap.py` 仅为 **compat re-export**，勿再加业务逻辑。

## 步骤 5 · 取证入账 + 按需出包（mint / export）

> 账本：`--mint` / `--refresh` / `--auth-status`（源=auth.json）。远端 CLIProxy：`--cpa-upload` / `--cpa-list`。

**目标**：SSO → RT/AT → **`auth.json`**；需要 CLIProxy / sub2api 时再 export。

```text
mint 默认：只写 auth.json（不写 cpa_export）
export：   从 auth.json 出 pack（cpa_files ≡ sub2api 同级）
```

### 5A · mint（入账本）

```bash
# 推荐：只 mint「sso_roster 有 SSO、auth.json 尚无该邮箱」的号
python main.py --mint all --mint-missing --no-probe

# 单号
python main.py --mint 邮箱@domain --no-probe

# 并发（可开大；device/code 自带间距 + 429 退避，不砍 -j）
python main.py --mint all --mint-missing --no-probe -j 8

# 例外：mint 时顺带写 cpa 文件（一般不必；用 5B export 更清晰）
python main.py --mint 邮箱 --mint-write-cpa --no-probe
```

| 开关 | 含义 |
|------|------|
| `--mint-missing` | `auth.json` 已有该邮箱 → skip（**不是**看 cpa 文件） |
| 无 missing | `all` = 全员再 mint 入账 |
| `--mint-write-cpa` | mint 时额外写 `cpa_export`（默认关） |
| `--no-probe` | 写完不探活（探活放到步骤 7） |
| `-j N` | 并发；入口闸门削 device/code 尖峰，**无需故意压 j** |

结束行：`ok=… fail=… skipped_existing=…`；池已齐则 `nothing missing in auth.json`。

### 5B · export pack（按需）

```bash
# sub2api UI 导入包（外壳 exported_at/proxies/accounts）
python main.py --export sub2api --export-only 邮箱
python main.py --export sub2api
python main.py --export sub2api --export-dry-run

# CLIProxy 本地文件（给步骤 8 上传）
python main.py --export cpa --export-only 邮箱
python main.py --export cpa

# Cockpit Tools 本地导入（数组批文件 + 一号一文件）
python main.py --export cockpit --export-only 邮箱
python main.py --export cockpit
python main.py --export cockpit --export-dry-run

# 旧别名仍可用
python main.py --sub2api-export 邮箱
```

| pack | 输出 | 用途 |
|------|------|------|
| `cpa_files` | `cpa_export/xai-*.json` | CLIProxy / `--cpa-upload` |
| `sub2api` | `sub2api_export/grok-*.json` | sub2api UI / **`--sub2api-upload` 远程导入** |
| `cockpit` | `cockpit_export/grok-*.json` + `grok_accounts.json` | Cockpit Tools 粘贴/导入（无远端 upload） |

> `--cpa-missing` 是步骤 8 **上传**用的，不是 mint。  
> `--mint-missing` = 账本补洞；`--export` = 从账本出文件。  
> **远程 sub2api**（可选）：本地有 pack 后  
> `python main.py --sub2api-upload all`  
> 或 `python main.py --sub2api-upload EMAIL --sub2api-from-auth`  
> 凭据：`SUB2API_BASE_URL` + `SUB2API_ADMIN_EMAIL` + `SUB2API_ADMIN_PASSWORD`  
> API：`POST /api/v1/admin/accounts/data`（与 UI 数据导入同路径）

**通过**：`auth.json` 有目标号 AT+RT；若要上传远端，再有对应 `cpa_export/xai-*.json`。

## 步骤 6 · 保活 token（refresh / remint）

**目标**：access 可用；rt 被 revoke 时自动用 SSO 重 mint，不死刷。

### 操作

```bash
# 先只看谁该刷（只读、不打网）
python main.py --auth-status all
python main.py --auth-status all --needs-refresh-only

# 推荐日常（串行）
python main.py --refresh all --needs-refresh-only --remint-on-revoke --no-probe

# 并发（同 -j；可开 4~8；refresh/remint 以 auth.json 为准；需要 cpa 文件时再 --export cpa）
python main.py --refresh all --needs-refresh-only --remint-on-revoke --no-probe -j 8

# 调试只跑前 N 个
python main.py --refresh all --needs-refresh-only --remint-on-revoke --no-probe -j 4 --limit 20
# 进度行以 # 开头；ASCII 图标：加 --ascii-log
python main.py --refresh all --needs-refresh-only --limit 5 --ascii-log

# 放宽：剩余 ≤30 分钟也刷
python main.py --refresh all --needs-refresh-only --skew-min 30 --remint-on-revoke --no-probe -j 4

# 单号
python main.py --refresh 邮箱 --mint-probe-mode models
```

| 状态 / 现象 | 动作 |
|-------------|------|
| fresh | 可直接步骤 7 / 8 |
| needs_refresh / expired | refresh（needs-only） |
| `invalid_grant` / revoked | **remint**（`--remint-on-revoke` 或手动 mint） |
| 有 SSO 无 CPA | 回步骤 5 `--mint-missing` |
| 无 SSO 且 rt 死 | 无法 remint → 回步骤 3 补号 |

| 开关 | 行为 |
|------|------|
| `--needs-refresh-only` | 只刷快过期/已过期 |
| `--skew-min N` | 剩余 ≤N 分钟算 needs |
| `--remint-on-revoke` | 仅 revoked 时 SSO 覆盖 mint |
| `--limit N` | 调试：过滤后再最多处理 N 个（refresh/mint/auth-status） |
| `-j N` / `--jobs N` | 并发刷（默认 1） |
| 无 SSO | `remint_skip_no_sso`，不死刷 |
| 网络等其它错 | **不**自动 mint |

结束：分桶总结（**refresh_ok** / **remint_ok** / recovered / fail…）+ 一行机读 footer。
过程：每完成一个（≤100 全打；更大每 5 个）打印
`[done/total] kind email  refresh_ok=… remint_ok=… recovered=… fail=… rate=…/s eta=…s`。

**通过**：needs 列表清空或仅剩无 SSO 的 skip。

## 步骤 7 · 探活 / 查额度

**目标**：确认 token 能用；需要时看 **xAI 账单**、**限流窗** 或 **free 是否用尽**。

### 前置

| 项 | 说明 |
|----|------|
| 真源 | **`auth.json`**（ledger AT）；不读 `cpa_export` |
| 目标写法 | `all` 或 **单个邮箱**（勿逗号列表） |
| 代理 | mint/probe 默认 **LOCAL_PROXY**（与注册 hop1 同，通常 7890）；可用 `--mint-proxy` 临时覆盖 |
| 密钥 | 不需要；用池内 AT。过期则先步骤 6 `--refresh` |

```bash
# 代理示例（PowerShell / bash 按环境设）
# mint 跟 LOCAL_PROXY；临时: --mint-proxy http://127.0.0.1:7890
```

### 三套信号（别混）

| 套 | 从哪来 | 本地怎么看 | 回答什么 |
|----|--------|------------|----------|
| **A. xAI 账单** | `GET /v1/billing` + `?format=credits` | `--probe-mode billing` | 月/周**账期**、m_lim/used；**不是** free 用尽 |
| **B. 限流快照** | 响应头 `x-ratelimit-*` | `--probe-mode chat` / `quota` | 当前 req/tok 窗（≈ sub2api Grok usage） |
| **C. free 用尽** | 对话错误体 `free-usage-exhausted` | chat/quota 列 **`class`** | **是否用完**（对齐 CPA 插件 [grok-inspection](https://github.com/ywddd/grok-inspection)） |

```text
export / cpa 文件     → 只有 OAuth，不存周/月积分
billing 表            → month 账期 + week 账期（常 m_lim=0）
chat / quota 表       → class + req/tok；class 才判 free 用尽
裸 HTTP 429           → 先看 body：有 free-usage → 用尽；否则临时限流
```

### 如何使用（按场景）

#### 1）日常探活（不烧 chat）

```bash
python main.py --probe-quota all --probe-mode models -j 8
python main.py --probe-quota EMAIL --probe-mode models
# 截断：--limit 20
```

| 输出 | 含义 | 下一步 |
|------|------|--------|
| `status=200` `models=ok` | AT 活 | 可 export / 调度 |
| `401` / fail | 凭证问题 | 步骤 6 refresh/remint |

#### 2）看账单账期（不烧 chat；free 常全 0）

```bash
python main.py --probe-quota all --probe-mode billing -j 4
python main.py --probe-quota EMAIL --probe-mode billing
# 例: m_lim=0 used=0~49  month=…→…  week=…→…
```

- `m_lim=0` + 有日期 → 典型 free，**不能**据此说用完/未用完  
- 付费号才看 `m_lim/used/remaining` 或 `credit%`

#### 3）判 free 是否用完 + 限流窗（推荐）

```bash
# 单号
python main.py --probe-quota EMAIL --probe-mode chat

# 小批（会真实打 chat；并发别高）
python main.py --probe-quota all --probe-mode chat -j 2 --limit 30

# 账单 + chat 全景
python main.py --probe-quota EMAIL --probe-mode quota
```

**表头 `class`（C 套）+ req/tok（B 套）：**

| class | 含义 | 建议 |
|-------|------|------|
| `healthy` | 2xx，能打 | 可调度 / 可 export |
| `quota_exhausted` | **free 额度用尽**（24h 滚动） | **本轮不调度**；等窗或换号 |
| `rate_limited` | 裸 429，**不是**用尽 | 稍后重试，勿 disable |
| `reauth` | 401 / token 失效 | refresh/remint |
| `permission_denied` | 403/402 等 | 隔离，勿当用尽 |
| `probe_error` | 网络/超时等 | 复查后再动 |

汇总行示例：`ok=… fail=… free_exhausted=N rate_limited=M reauth=K`

**判定口诀：**

```text
要「用没用完」→ --probe-mode chat，看 class
  class=quota_exhausted          → 用完
  class=rate_limited             → 限流，不是用完
  class=healthy                  → 未用完
  class=reauth                   → 先修凭证
不要用 billing m_lim=0 / credit%=0 当「用完」
```

实现：`grokreg/oauth/probe_classify.py`（解析 body code/文案）；  
真用尽样例 code：`subscription:free-usage-exhausted`（可带 `tokens (actual/limit): a/b`）。

#### 4）抽样统计用尽率（可选脚本）

```bash
# 随机 N=100 chat 巡检 → output/quota_exhausted_n100.json
PYTHONPATH=. python scripts/quota_exhausted_n100.py

# 猎号（找满 2 个用尽即停等）见历史 output/quota_exhausted_hunt.json
```

实测参考（本池某次 N=100，seed=20260719）：**用尽率约 4%**；用尽集中在 `outlook.com`，CloudMail 域样本可为 0。以你当次 `stats` 为准。

### mode 速查

| mode | 探什么 | 烧 chat | 并发建议 |
|------|--------|---------|----------|
| `models` | 活没活 / grok-4.5 | 否 | `-j 4~8` |
| `billing` | 月/周账期、m_lim/used | 否 | `-j 4~8` |
| `chat` | **class** + req/tok | 是 | `-j 2~3` |
| `quota` | billing + chat | 是 | 单号/小批 |
| `both` | models 后 chat | 是 | 小批 |

常用参数：`--limit N` · `-j N` · `--probe-interval SEC` · `--probe-retries N` · `--probe-timeout SEC` · `--mint-proxy URL`

### 别混

| 别混 | 是 | 不是 |
|------|----|------|
| models | 能否列模型 | 额度数字 |
| billing | xAI 月/周**账期** | free 是否用尽；sub2api 的 21/2M |
| chat class | free 用尽 / 限流 / 重登 | billing 的 m_lim 是否为 0 |
| bare 429 | 可能限流或用尽 | 必须看 body / class |
| export 文件 | OAuth | 周/月积分 |

**免费号常见**：billing `m_lim=0`，month/week 日期仍有；`used` 可非零仍 `healthy`。  
**sub2api 新号 usage 空**：对该号 Test/聊一句 → 刷 usage → 期望 `observed`。  
**用尽后**：约 24h 滚动恢复；未自动写 ledger 标记时，以当次 `chat` 为准。

**通过**：models `status=200`；判用尽以 `class=quota_exhausted` 为准；401 → 回步骤 6。
