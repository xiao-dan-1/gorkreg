## 4. Step 1 — 预热与动态刮取

### 4.1 请求

```http
GET /sign-up HTTP/2
Host: accounts.x.ai
accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
sec-fetch-site: same-site
sec-fetch-mode: navigate
sec-fetch-dest: document
referer: https://console.x.ai/
```

### 4.2 必须刮取

#### A. `next-action`

- 形态：42 位 hex
- 样本（本地 HAR 当前）：
  ```text
  7f50061dd2f5b389a530e4a048d5fdf0c48d1d9259
  ```
- 参考仓库旧值（仅文档，不可写死）：
  ```text
  7f5c12078de072886cfb0e08eae73e54745587675d
  7f69646bb11542f4cad728680077c67a09624b94e0
  ```

刮法：
1. HTML 中收集 `/_next/static/chunks/*.js`
2. 下载 chunk
3. 优先命中含以下关键字的 chunk：
   - `createUserAndSessionRequest`
   - `emailValidationCode`
4. 在该 chunk 内取 `"([a-f0-9]{42})"`
5. **42 位 hex 即完整 next-action**（不要再前置 metadata）

#### B. `next-router-state-tree`

来源：页面 RSC `self.__next_f.push` 中 router tree  
编码：URL-encode 后的 JSON 数组字符串

参考 fallback（仅离线对照）：
```text
["",{"children":["(app)",{"children":["(auth)",{"children":["sign-up",{"children":["__PAGE__?{\"redirect\":\"cloud-console\"}",{}]}]}]}]},"$undefined","$undefined",16]
```

#### C. Turnstile sitekey

默认/实测：
```text
0x4AAAAAAAhr9JGVDZbrZOo0
```

HTML 匹配优先：
```text
data-sitekey="0x4..."
sitekey: "0x4..."
```

#### D. Castle public key

参考：
```text
CASTLE_PK = pk_p8GGWvD3TmFJZRsX3BQcqAv9aFVispNz
```

## 5. gRPC-web 公共格式

### 5.1 请求头

```http
content-type: application/grpc-web+proto
x-grpc-web: 1
x-user-agent: connect-es/2.1.1
accept: */*
origin: https://accounts.x.ai
referer: https://accounts.x.ai/sign-up
sec-fetch-site: same-origin
sec-fetch-mode: cors
sec-fetch-dest: empty
```

### 5.2 帧格式

```text
+------+----------------+----------+
| flag | length(uint32) | payload  |
| 1B   | big-endian     | protobuf |
+------+----------------+----------+

请求: flag = 0x00
响应: message frame(s) + trailer frame(flag=0x80)
trailer 示例: b"grpc-status:0\r\n"
```

### 5.3 protobuf 编码（仅 string 字段）

```text
field tag = (field_no << 3) | 2
然后 varint(len) + utf8_bytes
```

Python 等价：
```python
def pb_string(field: int, value: str) -> bytes:
    raw = value.encode("utf-8")
    tag = (field << 3) | 2
    return varint(tag) + varint(len(raw)) + raw

def grpc_frame(body: bytes) -> bytes:
    return b"\x00" + struct.pack(">I", len(body)) + body
```

### 5.4 成功判定

```text
HTTP 200
且 trailer 中 grpc-status == 0
```

空 body：
```text
常见原因:
- 邮箱域名拦截
- Cloudflare 挑战
- 代理/指纹异常
```

## 11. Step 7 — create_account / POST sign-up

这是整条链路最关键一步。

### 11.1 URL

```text
POST https://accounts.x.ai/sign-up
可选: ?redirect=cloud-console
```

### 11.2 请求头（必须）

```http
accept: text/x-component
content-type: text/plain;charset=UTF-8
next-action: <动态刮取的 42-hex>
next-router-state-tree: <URL-encoded tree>
origin: https://accounts.x.ai
referer: https://accounts.x.ai/sign-up
sec-fetch-site: same-origin
sec-fetch-mode: cors
sec-fetch-dest: empty
```

注意：
- **content-type 不是 application/json**
- any-auto-register 用 json 是简化版，与真实流量不一致

### 11.3 Body 结构

Content 是 **JSON 文本**，但 header 仍是 `text/plain;charset=UTF-8`。

数组 2 项：

```json
[
  {
    "emailValidationCode": "EQ0ODK",
    "createUserAndSessionRequest": {
      "email": "user@example.com",
      "givenName": "Alice",
      "familyName": "Smith",
      "clearTextPassword": "YourPassword123!",
      "tosAcceptedVersion": "$undefined"
    },
    "turnstileToken": "<turnstile token>",
    "conversionId": "806733ff-ba51-4928-b62c-f682857d962b",
    "castleRequestToken": "<castle token ~18-20KB>"
  },
  {
    "client": "$T",
    "meta": "$undefined",
    "mutationKey": "$undefined"
  }
]
```

序列化要求：
```text
json.dumps(args, separators=(",", ":"))
不要 pretty-print
```

### 11.4 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| emailValidationCode | 是 | 刚验过的 6 位码 |
| createUserAndSessionRequest.email | 是 | 同发码邮箱 |
| givenName / familyName | 是 | 随机名即可 |
| clearTextPassword | 是 | 明文密码 |
| tosAcceptedVersion | 是 | 参考实现可用 `"$undefined"`；也可试 `1` |
| turnstileToken | 是 | 硬门槛 |
| conversionId | 是 | 每轮 UUID v4 |
| castleRequestToken | 高相关 | 真实浏览器约 18–20KB；硬门槛之一 |
| 第 2 项 client=$T | 是 | Next.js action 形态 |

### 11.5 反机器人三件套（不能离线伪造）

```text
1. turnstileToken
2. castleRequestToken
3. cf_clearance（若触发 CF 挑战）
```

YesCaptcha：
- 支持 Turnstile
- **不支持 Castle**

因此最小骨架可先：
1. 有 turnstile
2. castle 先空 / 占位 / 外部注入
3. 用成功率评估是否必须先解决 Castle

### 11.6 响应

#### HTTP

```text
成功传输: 通常 HTTP 200
body: Next.js RSC flight 文本
常见开头: 2:"$Sreact.fragment" ...
```

#### 成功信号

优先级：
1. body 中出现 `set-cookie?q=eyJ...` hop URL
2. 后续能提取 `sso`
3. 无 hard error

#### 失败信号

```text
next_action_error:...
wke=email:invalid-validation-code
wke=... 其他业务码
explicit account_* / turnstile error
HTTP != 200
```

错误解析优先顺序：
1. `^\d+:E{...}` Next action hard error
2. `wke=...`
3. JSON `"error":"[invalid_argument]..."`
4. 明确业务短语（避免误匹配 JS chunk 中的英文）

## 12. Step 8 — SSO 提取

### 12.1 目标 cookie

```text
sso      # JWT，payload 常见含 session_id
sso-rw   # 读写会话相关
```

### 12.2 主路径

```text
1) create_account 响应 Set-Cookie 里是否已有 sso
2) RSC body 是否直接嵌入 sso=eyJ...
3) 从 RSC body 解析 set-cookie?q=<JWT> URL
4) 解码 JWT.config.success_url
5) 逐跳 GET hop URL（保留 cookie jar，注意 302/303）
6) 从 Set-Cookie / cookie jar 读 sso
```

### 12.3 URL 形态

```text
https://auth.xxx/set-cookie?q=eyJhbGciOi...
https://auth.xxx/set-cookie/?q=eyJ...
相对路径 /set-cookie?q=eyJ...
```

需做反转义：
```text
\u0026 -> &
\u003d -> =
\u003f -> ?
\/     -> /
&amp;  -> &
```

### 12.4 hop 解码

JWT payload 中：
```json
{
  "config": {
    "success_url": "https://auth.grokusercontent.com/set-cookie?q=..."
  }
}
```

参考实现备注：
- 旧 3 跳（grokipedia → grokusercontent → grok.com）部分退役
- 当前更关键 hop 常是 `auth.grokusercontent.com`
- 仍应兼容多 host

### 12.5 fallback 顺序（工程化）

```text
create Set-Cookie
→ RSC 内嵌 sso=
→ RSC set-cookie 链
→ https://auth.x.ai/set-cookie
→ https://auth.grokusercontent.com/set-cookie
→ https://accounts.x.ai/
→ https://grok.com/
→ cookie jar 扫描
```

### 12.6 hop 请求头示例

```http
accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
sec-fetch-site: cross-site
sec-fetch-mode: navigate
sec-fetch-dest: document
referer: https://accounts.x.ai/
```

- 写死 next-action

## 16. 已知错误与对策

| 现象 | 可能原因 | 对策 |
|---|---|---|
| `wke=email:invalid-validation-code` | 码过期 / 验后等待过久 | 先验 turnstile，验码后立刻 create |
| create HTTP 200 但无 sso | 业务失败被包在 RSC / hop 失败 | 解析 wke / hard error；打印 body 前 500 字；走 fallback hop |
| gRPC 空 body | CF / 域名 / 指纹 | 检查代理、impersonate、是否需 cf_clearance |
| next-action 失效 | 部署更新 | 重新 load_signup_page 刮取 |
| 短密码反复失败 | 强度策略 | 换更长更复杂密码，可先 ValidatePassword |
| 有 turnstile 仍失败 | 缺 castle / cf | 补 castleRequestToken |
| HAR 无 Set-Cookie | Chrome 脱敏 | 不要用 Chrome HAR 当 cookie 证据 |
